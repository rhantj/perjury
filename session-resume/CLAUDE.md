# session-resume/

세션이 끊겨도 다음 사람이 이어받을 수 있게 하는 **진행 상황 스냅샷**.
다음 사람은 내일의 나일 수도, 팀원일 수도 있다. 둘 다 읽을 수 있게 쓴다.

프로젝트 규칙은 루트 [CLAUDE.md](../CLAUDE.md)에 있다.

---

## 파일 규칙

- 파일명: `YYYY-MM-DD-<주제>.md` (예: `2026-08-02-rule-engine-tdd.md`)
- 주제는 영어 kebab-case. 같은 날 여러 번 쓰면 주제로 구분한다.
- **이 폴더는 커밋된다.** public 리포에 그대로 올라간다는 전제로 쓴다 —
  키·토큰·개인 메모는 넣지 않는다.
- 과거 파일은 고치지 않는다. 상황이 바뀌면 새 파일을 쓴다. 이건 로그지 문서가 아니다.

## 막힌 것

증상 → 시도한 것 → 남은 가설 순으로 쓴다. 해결됐으면 이 절은 비운다.

- 증상: `noUncheckedIndexedAccess` 때문에 카드 배열 접근이 전부 undefined 분기
- 시도: 튜플 타입으로 고정 → 카드 수가 데이터라 실패
- 남은 가설: 배분 시점에 한 번 좁히고 이후엔 좁혀진 타입으로 전달

## 쓸 때 지킬 것

- **"다음에 어디부터"가 이 파일의 핵심이다.** 완료 목록만 있고 재개 지점이 없으면 쓸모가 없다.
- 완료 항목은 근거(파일·커밋·테스트 수)를 붙인다. "구현했다"만 쓰지 않는다.
- 검증 상태는 **실제로 돌려본 결과**를 적는다. 안 돌려봤으면 "미확인"이라고 쓴다.
- 결정("왜 이 구조인가")은 여기 쓰지 말고 `docs/decisions/`로 보낸다. 여기는 스냅샷, 거기는 영구 기록이다.
- 실패·미완을 그대로 쓴다. 다음 사람이 같은 벽에 다시 부딪히는 걸 막는 게 목적이다.
