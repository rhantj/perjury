### 3단계 — 화면에 그리기 (`8b950a6`, `5f80708`)

| 어디 | 무엇 |
|---|---|
| 좌석 `Table.tsx` | 제안·반증·이의제기 대사 |

- **대체가 아니라 병기.** LLM이 카드 이름을 말하지 않을 수 있어서, 대체하면
  «무엇으로 반증했는지»가 화면에서 사라진다.
- 대사가 null이면 지금까지의 화면과 완전히 같다(사람·규칙 기반·폴백) — 절대 규칙 4.
- 반증 대사는 B의 순차 공개(`revealed`) 조건을 똑같이 탄다. 대사만 먼저 뜨면 순서가 깨진다.

### 워커 회귀 수정 (`1eba961`)

**시야에 필드를 추가하자 워커가 정상 요청을 거부했다.**
`workers/src/schema.ts`는 화이트리스트 검증이라 모르는 키가 하나만 있어도 요청 전체를 버린다.

```
{"ok":false,"code":"invalid_request","message":"rounds[0]: 허용되지 않은 필드 'suggestionLine'"}
```

대사 필드를 받도록 고치고 **80자 제한**을 걸었다 — 이 값은 다음 호출의 프롬프트에 그대로
실려 돌아간다. 프론트도 60자로 자르지만 프론트는 위조 가능하므로 워커가 진짜 벽이다.

## 이번에 배운 것 — 다음에 또 걸린다

### 1. 시야에 필드를 더하면 워커 검증이 깨진다

`src/engine/view.ts`의 `GameView`에 필드를 추가할 때마다 **`workers/src/schema.ts`의
`onlyKeys` 목록을 같이 고쳐야 한다.** 타입은 통과한다(워커가 같은 타입을 import하지만
검증은 런타임 화이트리스트라 타입 검사에 안 걸린다). 테스트도 통과한다(프론트 테스트는
워커를 안 부른다). **배포하고 실제로 눌러봐야만 드러난다.**

### 2. 폴백이 고장을 숨겼다

LLM이 완전히 죽었는데 게임은 끝까지 굴러갔다. 절대 규칙 4가 제 일을 한 것이지만,
화면상으로는 «대사만 안 뜬다»로 보였다. 폴백이 침묵하면 LLM이 죽은 걸 아무도 모른다.

→ **`fallbackReason` 배너(B 담당)의 우선순위가 올라갔다.** 이건 편의 기능이 아니라
진단 장치다. 심사 중에 조용히 폴백으로 떨어지면 그대로 넘어간다.

### 3. HTTP 상태 코드만 보면 못 잡는다

네트워크 탭에는 `/decide` 200이 줄줄이 찍혔는데 **본문이 `ok:false`였다.**
프론트는 본문의 `ok`를 보고 던진다. 진단은 브라우저 콘솔에서 `fetch`를 감싸
응답 본문을 모아 보고서야 됐다:

```js
const orig = window.fetch
window.fetch = async (...a) => {
  const r = await orig(...a)
  if (String(a[0]).includes('/decide')) r.clone().json().then((j) => console.log(j))
  return r
}
```

## 미완 · 다음 액션

**다음에 여기부터:** `workers/src/prompt.ts`의 `observationBlock`.

- [ ] **대사가 아직 프롬프트에 안 들어간다.** 시야에는 실려 워커까지 오는데
      `observationBlock`이 `claimText(d.claim)`만 렌더하고 `line`을 무시한다.
      **즉 에이전트들은 서로의 말을 아직 못 읽는다.** 1단계에서 «실어야 남의 말에
      반응할 수 있다»고 했던 것의 절반만 된 상태다 — 배관은 깔렸고 프롬프트가 안 쓴다.
      넣으면 프롬프트가 커지므로 비용도 함께 봐야 한다(변동 블록이라 캐시 대상이 아니다).

      `Table.tsx`·`Log.tsx` 양쪽에 같은 문장이 있다. 대사와 나란히 놓이니 더 눈에 띈다.

## 팀에 전달

- **`GameView`에 필드를 더하면 `workers/src/schema.ts`를 같이 고쳐야 한다.**
  안 고치면 워커가 모든 요청을 거부하고, 폴백이 받아내서 **조용히 LLM만 죽는다.**
  타입 검사도 테스트도 안 잡는다. 이번에 실제로 당했다.
- **워커를 고쳤으면 `npm run worker:deploy`를 따로 돌린다.** 프론트 배포와 별개다.
- **대사를 쓰는 곳은 세 군데다**: `view.rounds[N].suggestionLine` /
  `declarations[].line` / `challenge.line`. 없으면 `null`이므로 고정 문구로
  되돌아가는 분기를 반드시 남긴다.
- **`Decider` 반환 타입이 `Spoken<T>`다.** 대사가 없으면 `silent(값)`으로 감싼다.
