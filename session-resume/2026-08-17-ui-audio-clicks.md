### 버튼 연결 — `src/audio/ui-clicks.ts` (116줄, 신규)

버튼마다 `onClick`에 달지 않았다. 버튼이 **아홉 파일에 서른여덟 개** 있어서
하나씩 다는 것은 앞으로 잊어버릴 서른아홉 번째 자리를 만드는 일이다.

- `document`에서 클릭을 **한 번만** 받아 눌린 버튼의 성격을 읽는다.
- 성격은 **BEM 클래스명**에서 읽는다. 이 프로젝트는 클래스명이 이미 뜻을 담고 있어서
  (`briefing__back`, `btn--ghost`) 없는 규칙을 새로 만드는 것보다 어긋날 자리가 적다.
- 틀리면 `data-sfx`로 덮어쓴다. 그쪽이 언제나 이긴다. `data-sfx="none"`은 소리 없음.
- **거품 단계**에서 받는다. 잡기 단계로 옮기면 아래 겹침 판정이 깨진다.

### 게임 소리와 겹치지 않기 — `src/audio/audio.ts`

제안·반증·지목 버튼은 이미 자기 소리가 있다. 거기에 「톡」을 얹으면 도장 소리
앞머리만 지저분해진다. 버튼마다 예외를 적는 대신 **소리 쪽에서 판단**하게 했다.

- `sincePlaySfx()` — 마지막 «판의 소리»로부터 지난 시간. `ui*`는 여기 기록하지 않는다.
- 160ms 안에 겹치면 조작음을 건너뛴다. 새 행동을 추가해도 `ui-clicks.ts`를 안 고쳐도 된다.

### 표지 배경음 — `tryUnlock()` + 기존 폴백

브라우저는 **사용자가 페이지를 건드리기 전의 재생을 정책으로 막는다.** 우회할 수 없다.
다만 허용 여부가 방문자마다 다르므로(Chrome은 Media Engagement Index로 판단) 두 경로를 겹쳤다.

1. `GameScreen.tsx` 마운트에서 곡을 먼저 걸고 곧바로 `tryUnlock()`. 허용되면 클릭 없이 올라온다.
2. 막히면 `bindFirstGesture`(pointerdown·keydown·touchstart)로 첫 조작을 기다린다.

**폴백을 지우면 안 된다.** 처음 오는 사람에게는 그쪽이 유일한 경로다.

`engine.ts`에 `resumeAsync(): Promise<boolean>`을 더했다. `resume()`과 달리 결과를 돌려준다 —
**자동재생이 막혀도 약속이 거부되지 않고 그냥 suspended로 남는 브라우저가 있어서**,
거부만 잡으면 성공했다고 잘못 읽는다. 상태를 다시 확인한다.

### 음소거 버튼만 예외 — `src/components/MuteButton.tsx`

`data-sfx="none"`으로 위임에서 빼고 직접 낸다. **순서가 전부다** — 끄면 그 뒤로
아무 소리도 안 나므로 「껐다」는 끄기 **전**에, 「켰다」는 켠 **뒤**에 내야 한다.
위임 리스너는 React `onClick` 다음에 돌아서 이 순서를 만들 수 없다.

### 남은 판단 — 여러 판 돌려봐야 갈리는 것

값만 고치면 되므로 막힌 것은 아니다. 다만 **한두 번 들어서는 안 갈린다.**

- **`uiPaper` 호버음 피로도.** 요청으로 2.4배 올렸다(`0.055 → 0.13` 등). 호버는 클릭보다

## 막힌 것

해결된 것만 남긴다. **같은 벽에 다시 부딪히지 않기 위한 기록이다.**

### 「소리가 안 들린다」가 두 번 나왔는데 원인이 서로 달랐다

**1차 — 출력단에 천장이 있었다** (전날 작업, 이번에 확인)

- 증상: 개별 게인을 올려도 전체가 작았다.
- 원인: `softClip` 곡선 `x − 0.28x³`이 입력 1에서 **0.72를 내놓는데** 그 뒤에 되돌리는
  단이 없었다. 값을 올려도 천장이 따라 내려왔다.
- 해결: WaveShaper 뒤에 makeup 게인(1.38)과 낮은 리미터 문턱. 개별 값이 아니라 구조 문제였다.

**2차 — 음역이 틀렸다** (이번)

- 증상: 시나리오 클릭음(`uiHeavy`)이 «안 들린다».
- 처음 가설: 게인이 작다 → **틀렸다.**
- 실제 원인: 무게를 **68~90Hz**에 뒀는데 **노트북 스피커가 그 대역을 사실상 못 내보낸다.**
  게인을 올려도 «안 나오는 대역이 조금 더 세게 안 나올» 뿐이다.
- 해결: 무게를 **150~600Hz**로 올렸다. 둔탁함은 저역이 아니라 **고역이 없는 것**에서
  나오므로, 음역을 올려도 위를 비워 두면 둔탁함은 유지된다.

> **다음 사람에게:** 「소리가 작다」는 말이 나오면 게인부터 올리지 말고
> **그 소리가 어느 대역에 있는지** 먼저 본다. 200Hz 아래는 노트북 스피커에서 없는 것과 같다.

### 문 닫히는 소리를 네 번 다시 만들었다 (전날 → 이번에 종결)

- 증상: 「퇴출」이 문이 아니라 북으로 들린다. 사용자가 네 번 거절했다.
- 진단이 매번 바뀌었다:
  1. 삐걱이 톱니파 신스였다 → 마찰(stick-slip) 알갱이로 다시 만듦
  2. `sine 112→36 + FM`은 **문자 그대로 킥드럼 합성법**이었다 → 제거
  3. `bandpass 168 Q3.4/0.5s`는 톰, `92 Q5/0.6s`는 플로어톰이었다 → Q<1 잡음으로 교체
  4. 빗장이 타격보다 0.3초 뒤에 있었다 → **30ms 안으로 겹침**, 비정수비 나무 판 6모드 추가
- 교착을 깬 방법: 한 번 더 추측하는 대신 **축을 벌린 후보 3종**(나무/쇠/마른)을 만들어
  나란히 듣게 했다. A(나무)로 확정.

> **다음 사람에게:** **음정이 잡히고 감쇠가 길면 그건 북이다.** 타격음은 Q<1 잡음의
> **과도 현상**이어야 한다. 그리고 문의 정체성 절반은 **나무 타격과 쇠 빗장의 시간 겹침(30ms 이내)**이다.

## 팀에 전달

- **버튼을 새로 만들 때 소리를 따로 붙이지 않아도 된다.** `ui-clicks.ts`가 클래스명을 보고
  자동으로 배정한다. 성격이 다르면 그때만
  `data-sfx="tap|heavy|paper|confirm|back|toggleOn|toggleOff|none"`을 적는다.
- **자기 소리가 있는 버튼(제안·반증·지목)에는 예외를 적지 않아도 된다.** 소리 쪽에서
  160ms 겹침을 보고 알아서 건너뛴다.
- **표지 배경음이 안 나는 것은 버그가 아닐 수 있다.** 시크릿 창이나 그 사이트에 처음 오는
  브라우저에서는 자동재생이 막힌다. 화면 아무 데나 한 번 클릭하면 올라온다.
  **심사자가 처음 열 때가 이 경우일 수 있다** — 코드로 더 밀어붙일 수 있는 한계가 아니다.
- 소리 계통 파일 배치: `engine.ts`(바닥) → `voices.ts`(재료) → `synth.ts`(배치표) +
  `sfx-actions.ts` / `sfx-outcomes.ts` / `sfx-ui.ts`(레시피) + `drone.ts`(배경음).
  전부 800줄 아래다(최대 `engine.ts` 788줄).
- **음원 파일은 여전히 0개다.** 전부 그 자리에서 합성한다. 진짜 음원을 넣고 싶으면
  `src/assets/audio/<이름>.mp3`로 두면 코드를 안 고쳐도 그쪽이 이긴다(`audio.ts` 머리말 참고).
