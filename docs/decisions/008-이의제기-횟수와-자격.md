# 008 — 이의제기 횟수 제한과 자격 조건

**결정일** 2026-08-05
**상태** 확정
**관련** [01-game-design.md §1.6](../01-game-design.md) · [001-반증-공개와-이의제기.md](001-반증-공개와-이의제기.md)

## 무엇을 정했나

한 사람의 이의제기에 두 가지 제약을 건다.

| | 규칙 |
|---|---|
| 횟수 | 판당 **2회**까지 |
| 자격 | 아직 공개되지 않은 손패가 **1장 이상** 있어야 함 |

## 왜

### 발단

플레이 중 「오판 2번이면 패 2개가 다 까지는 것 아니냐, 밸런스가 안 맞는 것 아니냐」는
지적이 나왔다. 확인해 보니 사실이고, 원래 규칙에서 따라 나오는 결과였다.

`src/engine/challenge.ts`의 판정은 이렇다.

- 성공 판정은 「내가 그 카드를 갖고 있는가」다. 카드는 유일하므로 내가 쥐고 있으면
  상대의 반증은 거짓이다.
- **성공하면** 증명하려고 내 카드를 공개한다.
- **실패하면** 벌로 내 카드가 공개된다.

즉 **이의제기는 이기든 지든 내 패 1장을 소모한다.** 손패는 2장이므로(`HAND_SIZE = 2`)
두 번이면 손패가 전부 공개된다. 손패가 전부 공개된 사람은 더 이상 위증할 수 없다 —
모두가 그의 패를 아니까. 이 게임의 핵심 행동에서 사실상 퇴장한다.

### 진짜 문제는 그다음이었다

페널티로 깔 카드를 고르는 `pickHidden`은 남은 게 없으면 `null`을 돌려주고,
그러면 `reveals`가 비어 아무 일도 일어나지 않는다.

> **3번째 이의제기부터는 비용이 0이다.**

가장 많이 틀린 사람이 가장 자유롭게 이의제기를 남발할 수 있게 되는 역전이다.
이건 밸런스 취향이 아니라 규칙의 구멍이다.

### 왜 두 조항 다인가

한쪽만으로는 막히지 않는다.

- **횟수만 묶으면**: 손패는 이의제기 말고도 비는 길이 있다. 위증하다 두 번 걸리면
  내가 한 번도 이의제기를 안 하고도 패가 전부 공개된다. 그 상태에서 남은 횟수는
  여전히 비용이 0이다.
- **자격만 걸면**: 구멍은 막히지만 횟수는 안 묶인다. 규칙이 「사실상 2회」인데
  화면에 드러나지 않아, 플레이어가 패가 닳는 걸 두 번 겪고 나서야 알게 된다.

횟수는 **양**을 묶고, 자격은 **값**을 보장한다. 역할이 다르다.

## 고른 것과 버린 것

| 안 | 판단 |
|---|---|
| **채택** 판당 2회 + 자격 조건 | 새 개념을 만들지 않는다. 자격은 §1.6(증명은 카드로 한다)의 귀결일 뿐이다 |
| 기각 — 다음 라운드 제안권 상실 | 새 상태와 새 규칙이 늘어난다. 값을 붙이는 목적에 비해 비싸다 |
| 기각 — 실패 시 신뢰도 하락 | 신뢰도가 승패 판정에 쓰이지 않아 «벌»로 체감되지 않는다 |
| 기각 — `HAND_SIZE`를 3으로 | 페널티 곡선은 완만해지지만 카드 15장 배분이 통째로 바뀐다. 파급이 크다 |

## 구현 시 지킬 것

- **횟수는 새 상태로 두지 않는다.** `state.rounds`에서 `challenge.challengerId`를 세면
  나온다. 상태를 늘리면 되감기·재현에서 어긋날 자리가 하나 더 생긴다.
- **룰 엔진은 순수 함수다.** 자격·횟수 위반은 엔진이 거절하고, 화면은 애초에
  누를 수 없게 막는다. 두 겹이지만 판정의 주인은 엔진 하나다.
- 화면에 남은 횟수를 보여준다. 규칙이 있는데 안 보이면 없는 것과 같다.

## 곁다리로 발견한 결함

이의제기 **성공** 시 증명 카드를 `reveals`에 **이미 공개된 것이어도 무조건** 넣는다.
그래서 `revealed` 배열에 같은 카드 id가 두 번 쌓일 수 있다. 화면에서 같은 카드가
두 장 그려지고 React 키가 충돌한다.

화면 쪽은 중복을 걷어내 막아 두었으나(`Table.tsx`), 근본 해결은 엔진이다.
이 결정을 구현할 때 같이 고친다.
