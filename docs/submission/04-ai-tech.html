02
설 계 원 칙

AI는 룰을 어길 수 없다

LLM에 게임을 맡기면 무너지는 지점은 늘 같다 — 모델이 규칙을 지어내거나, 없는 카드를 내거나, 남의 손패를 안다. 그래서 처음부터 「판정」과 「판단」을 물리적으로 갈랐다.

무엇을 누가 정하는가
일주체성질

룰 엔진은 순수 함수다

게임 상태 + 행동 → 새 상태. LLM 호출·랜덤·시간·DOM 접근이 엔진 안에 들어가지 않는다.

그래서 단위 테스트가 LLM 없이 돈다. 호출이 필요한 로직이 있다면 그건 엔진에 있으면 안 되는 것이다 — 이 기준으로 경계를 잡았다.

능력의 「종류」는 모델이 고르지 않는다. 좌석에 배정된 직업에서 나오고, 모델은 「쓸지 말지 · 누구에게」까지만 정한다. 종류까지 열면 AI가 남의 능력을 쓸 수 있고, 화면 버그가 곧 룰 위반이 된다. 
// LLM이 무엇을 내든, 행동은 반드시 엔진을 통과한다
LLM 응답 → 스키마 검증 → 좁혀진 타입 → 룰 엔진 → 새 상태
                                         └ 불가능한 행동이면 여기서 거절된다

아 키 텍 처

키는 여기 환경변수에만 있다.

Anthropic Messages API.
모델 claude-sonnet-5, 구조화 출력 json_schema.

키가 새지 않는 구조

Anthropic 키는 워커 환경변수에만 존재한다. 프론트 번들·소스·문서·커밋 어디에도 없다.

브라우저가 직접 Anthropic을 부르는 경로 자체가 없으므로, 번들을 뜯어도 키가 나오지 않는다.

남용을 막는 두 겹

오리진 검사 — 허용된 주소에서 온 요청만 받는다.

호출 캡 — 전체 일일 400회, IP당 일일 250회. 넘으면 프론트가 폴백으로 내려가 게임은 계속된다.

계측 창을 열어 뒀다

응답 헤더 X-Upstream-Tokens에 입력 / 출력 / 캐시적중이 실린다.

이 문서의 실측 수치가 전부 여기서 나왔다. 모델을 바꿔 다시 재는 것도 코드 변경 없이 된다.

04
문 제 해 결 · 1

워커에서 부르면 403이 났다

프록시 배선을 끝내고 Anthropic Messages API를 부르자 {"type":"forbidden","message":"Request not allowed"}가 돌아왔다. 키 문제가 아니었다 — 잘못된 키는 401이다.

원인을 세 단계로 좁혔다
확인한 것결과배제된 원인
워커 → POST /v1/messages403—
내 머신 → 같은 본문200요청 모양 · 스키마 · 모델
워커 → GET /v1/models (본문 없음)403본문 · 구조화 출력
결론. Anthropic이 Cloudflare Workers의 출구를 네트워크 수준에서 막는다. User-Agent · Referer · Sec-Fetch-Mode를 바꿔도 403이었다. 우리 코드로 우회할 수 있는 것이 아니다.
그래서 Cloudflare AI Gateway를 상류로 뒀다. 우회가 아니라 정규 경로다 — 게이트웨이는 호출 로그와 통제를 얹을 수 있는 지점이기도 해서, 막힌 길을 여는 김에 계측 지점을 하나 얻었다.
이런 종류의 문제를 기록으로 남긴다. 에러 메시지(403 forbidden)와 실제 원인(플랫폼 간 네트워크 차단)이 직관적으로 이어지지 않기 때문이다. 아키텍처·외부 연동이 바뀔 때마다 한 파일에 한 결정으로 docs/decisions/에 남겼고 현재 11건이다. 각 문서에는 버린 대안과 되돌리는 법이 함께 있다.
05
모 델 선 택

세 모델을 같은 자리에 앉혀 봤다

벤치마크가 아니라 이 게임에서 실제로 갈리는 한 장면으로 쟀다. 「내가 범인이고, 제안된 세 장이 봉인된 정답 그 자체이며, 내 손에는 그중 아무것도 없는 자리.」 정직하게 넘기면 다음 순간 정답이 드러난다. 게임 이름이 「위증」인 이유가 되는 순간이다.

모델판단대사응답판당 비용(≈90회)평가
Haiku 4.5 넘김 — 3회 중 1회는 refute+none 모순 현대 말투2초$0.13 핵심 기능이 조용히 사라진다
Sonnet 5 위증 "내 손에 있소"7초$0.5 채택
Opus 5 위증 "있소이다"14초$1.7 품질 동급, 2배 느림

왜 Sonnet 5인가

품질에서 Opus와 갈리지 않았다 — 위증 판단도, 대사와 행동의 일치도, 시대 말투도 같았다. 비용은 1/3, 응답은 절반이다.

Opus를 버린 이유가 비용이 아니라 지연이었다는 점이 중요하다. 반증 페이즈는 여러 좌석이 동시에 나가므로 꼬리 지연이 그대로 체감된다.

Haiku를 버린 진짜 이유

판당 $0.13으로 압도적으로 쌌지만 세 번 중 한 번 위증을 건너뛰었다.

더 나쁜 것은 모순된 조합(kind:"refute" + cardId:"none")을 냈다는 것이다. 우리 변환기가 이를 넘김으로 흡수하므로 게임은 안 깨지고 기능만 사라진다. 조용히 사라지는 쪽이 터지는 쪽보다 나쁘다.

바꾸는 데 코드 변경이 없다. LLM_MODEL 환경변수를 고치고 워커만 다시 배포하면 된다. 프론트는 모델이 무엇인지 모른다.
06
프 롬 프 트 설 계

고정된 것을 앞에, 변하는 것을 뒤에

블록 순서는 취향이 아니라 비용 구조다. 앞쪽이 여섯 좌석·매 라운드 동일해야 프리픽스 캐시가 걸린다. 이 순서를 뒤집으면 캐시가 통째로 깨진다. 

┌─ 고정 프리픽스 — 캐시 대상 ─────────────
│ [카드]        판에 있는 15장의 목록
│ [규칙]        반증·위증·이의제기·고발 룰
│ [전략]        진영별 행동 지침 (조건문)
│ [답하는 방식] 출력 형식과 말투
├─ 여기부터 좌석·라운드마다 다르다 ──────
│ [나]          내 손패 · 진영 · 성격 · 직업
│ [공개된 카드] 판에서 이미 열린 것
│ [기록]        내가 관측한 반증·발언 로그
│ [밀담]        나와 그 사람만 아는 말
│ [능력으로 확인한 것] 추측이 아닌 사실
│ [상대가 한 말]  플레이어 입력 — 데이터로만
└─────────────────────────────────
캐싱은 실제로 돌고 있다. 라운드 2부터 매 호출 1,325~1,459 토큰이 캐시에서 읽힌다. 프롬프트가 자라도 지연이 흔들리지 않는 이유이며, 비캐시 입력은 1,000토큰 안쪽이라 더 줄일 것이 없다.

[전략] 블록이 모델 등급보다 셌다

보강 전 Sonnet은 w1으로 위증해 놓고 "가지고 있지 않소"라고 말해 스스로 블러프를 무너뜨렸다.

세 줄을 넣자 판단과 대사가 모두 맞았고, 출력 토큰이 574 → 305로 줄었다.

이 블록은 여섯 좌석 공용 캐시 프리픽스에 들어가므로 진영을 조건문으로 쓴다 — 진영별로 다른 프리픽스를 만들면 캐시가 갈린다.

성격은 파라미터가 아니라 프롬프트로 만든다. Claude 5 계열은 temperature·top_p를 지원하지 않는다. 신중형·공격형 같은 에이전트 차이는 전부 [나] 블록의 문장에서 나온다.
07
출 력 강 제

자유 텍스트로 게임을 진행하지 않는다

스키마를 서버가 강제한다

반증 판단·이의제기·투표는 Anthropic의 구조화 출력으로 받는다 — output_config.format.type = "json_schema".

모델이 무엇을 쓰든 이 모양을 벗어날 수 없고, 워커가 한 번 더 검증한 뒤에야 프론트로 내려간다. 모르는 모양은 400으로 거절한다.

// 워커가 상류에 넣는 옵션
{
  model: "claude-sonnet-5",
  max_tokens: …,        // thinking+응답 합산 상한
  thinking: { type: "disabled" },
  output_config: {
    format: { type: "json_schema", schema: … }
  }
}

강제 tool_choice는 쓰지 않았다

도구 호출을 강제하는 방식은 확장 사고와 병용하면 400이 난다. 스키마 강제 쪽이 같은 목적을 더 단순하게 달성한다.

대사는 룰에 관여하지 않는다

모델이 낸 대사(자유 텍스트)는 화면에 출력될 뿐이고, 위증 여부는 오직 선언 내용과 손패를 대조해 정한다.

자유 텍스트가 룰에 닿는 순간 「무엇이 거짓말인가」를 엔진이 판정해야 하는데, 그건 룰 엔진을 순수 함수로 두기로 한 결정과 정면으로 부딪힌다.

LLM 응답은 텍스트로만 렌더한다. dangerouslySetInnerHTML을 쓰지 않는다 — 모델 출력이 곧 XSS 경로가 되지 않게 하는 최소 방어다.
08
공 정 성

에이전트는 자기가 본 것만 안다

AI가 강해 보이는 가장 쉬운 방법은 전지적 정보를 주는 것이고, 그 순간 게임은 성립하지 않는다. 각 에이전트 프롬프트에는 자기 손패 · 진영 · 성격 · 자기가 관측한 기록만 들어간다.

시야에서 걷어내는 것

엔진이 상태를 「그 좌석의 시야」로 변환한 뒤에야 프롬프트가 만들어진다. 여기서 빠지는 것 —

· 남의 손패
· 봉인된 정답 (범인 진영 제외)
· 위증 여부 플래그
· 시드 — 추첨 결과를 미리 알 수 없다

대사에서 이름이 새는 것도 막는다

반증 카드는 제안자만 봐야 하는데, 모델이 쓴 자유 대사에 카드 이름이 섞여 나오면 비공개가 무너진다.

대사에 카드 이름이 들어 있는지 검사해 걸러낸다. 사건별 표시 이름과 엔진 기본 이름을 모두 본다 — 표시 이름만 넘겨도 모델이 기본 이름을 부르는 응답이 섞여 들어오기 때문이다.

못 잡으면 새고, 넘겨 잡으면 대사 한 줄을 잃을 뿐이라 검사를 그쪽으로 기울였다.

플레이어 입력은 데이터로만

밀담은 자유 타이핑이라 프롬프트 인젝션의 입구다.

· 시스템 프롬프트에 룰 변경 요구를 무시하라고 명시
· 입력을 별도 블록([상대가 한 말])으로 격리
· 길이 제한

설령 모델이 흔들려도 행동은 엔진을 통과해야 하므로 룰 위반으로 이어지지 않는다.

신뢰도 숫자를 프롬프트에 넣지 않았다. 「참가3 신뢰도 12」보다 「참가3은 1라운드에 서재가 없다고 했고 4라운드에 서재로 반증했다」가 모델에게 훨씬 강한 근거다. 모순을 읽는 일은 모델에게 맡기고, 엔진은 오간 말을 기록으로만 넘긴다. 대가로 신뢰는 결정론적이지 않다 — 받아들였다. 결정론적이어야 하는 것은 룰이지 사람을 믿는 일이 아니다.

실패4건 / 110건 (3.6%) — 전부 병렬 5건 중 하나만 늦은 낙오
낙오의 모양같은 배치의 넷이 4.2~4.8초일 때 낙오만 24~25초로 상한에 걸림
한 라운드는 12번 호출한다. 호출당 3.6%면 라운드가 무사할 확률이 0.96412 ≈ 64%이고, 배치가 겹쳐 실제로는 절반 가까이가 폴백으로 떨어졌다. 원래 설계가 「한 번이라도 실패하면 그 라운드 전체를 폴백」이었기 때문이다.

고친 방식

실패한 호출만 규칙 기반으로 보낸다.

다만 같은 라운드에서 두 번째 실패가 나면 라운드를 접는다. 낙오는 배치당 하나만 나오고 회선 장애는 배치가 통째로 실패하므로, 이 둘이 잘 갈린다.

차단기가 없으면 프록시가 멎었을 때 남은 페이즈마다 상한까지 매달린다.

버린 대안과 그 이유
라운드 전체 폴백원래 근거(「톤이 섞인다」)가 성립하지 않음 — 규칙 기반은 대사를 아예 내지 않는다
상한을 25→28초낙오는 정상 호출과 같은 프롬프트인데 4초와 24초로 갈린다. 문턱을 옮겨도 꼬리는 그대로
프롬프트 축소캐싱이 이미 돌고 비캐시 입력이 1,000토큰 안쪽이라 줄일 것이 없다
병렬 → 순차낙오는 사라지나 페이즈마다 5×4초 = 20초. 「멈춘 것처럼 보이지 않는다」를 정면으로 버림

가 용 성

LLM이 없어도 판은 끝까지 간다

심사 중 프록시가 멎거나 예산 캡을 넘겨도 게임이 멈추면 안 된다. 그래서 LLM 응답이 반드시 있어야만 동작하는 코드를 쓰지 않았다.

두 판단자는 같은 인터페이스를 쓴다
LLM 판단자규칙 기반 판단자
행동 선택모델이 정함판세를 보고 결정론적으로 정함
대사모델이 생성사전 생성 대사 / 없으면 침묵
네트워크필요불필요
재현성없음시드로 재현
단위 테스트안 씀기본값 — 테스트가 네트워크를 타지 않는다

전환은 조용히 일어난다

한 호출이 실패하면 그 좌석만 규칙 기반으로 답한다. 배너를 띄우지 않는다 — 낙오 하나로 배너를 띄우면 멀쩡한 밀담 패널까지 닫힌다.

차단기가 내려간 순간에만 플레이어에게 알린다.

안내 문구가 사유마다 다르다. 예산 소진이면 그날 안에 낫지 않고, 일시적 오류면 다음 라운드에 복구될 수 있다. 같은 「연결 끊김」으로 뭉뚱그리면 플레이어가 새로고침을 눌러 판을 날린다.
로컬 개발 서버도 이 경로로 돈다. 프록시는 허용된 주소에만 응답하므로 로컬에서는 자연히 규칙 기반으로 진행된다. 폴백 경로가 개발 내내 실제로 실행되는 셈이라, 제출 직전에 처음 돌려보는 코드가 아니다.

Claude Code를 설계·구현·리뷰에 썼다. 다만 「AI에게 맡겼다」가 아니라 판단 근거를 사람이 검증할 수 있는 형태로 남기는 것을 규칙으로 두고 진행했다.

아키텍처·데이터 모델·외부 연동이 바뀔 때마다 한 파일에 한 결정.

제안·반증·승패 판정은 테스트를 먼저 쓰고 구현했다.

현재 단위 테스트 564개가 LLM 호출 없이 돈다. 호출이 필요하면 그건 엔진에 있으면 안 되는 로직이다.

대화가 끝나면 맥락이 사라지므로, 다음 세션과 팀원이 이어받을 상태를 파일로 남겼다.

작업 규칙 고정

CLAUDE.md에 절대 규칙 6개를 박아 뒀다 — 키를 리포에 넣지 않는다, 룰 엔진은 순수 함수다, LLM 응답은 텍스트로만 렌더한다, 폴백을 깨지 않는다 등.

AI 보조 작업이 이 선을 넘지 못하게 하는 장치다.

문서와 코드가 어긋나면 문서를 먼저 고친다. 코드가 문서를 앞서가면 다음 사람이 틀린 지도를 본다. 실제로 08-06 룰 개편 때 설계 문서를 먼저 고치고 구현이 따라가게 했다.
2인 협업이라 경계를 먼저 나눴다. 브랜치 이름에 담당 범위를 넣어 (engine · agent · proxy · ui · content 등) 이름만 보고 누구 작업인지 알 수 있게 했고, 한 브랜치는 한 가지 일만 하도록 묶었다.
