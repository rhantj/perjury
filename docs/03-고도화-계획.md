## 0. 전제

이 계획은 "다 만들자"가 아니라 **어디서 멈출지를 미리 정해두는 것**이다.

| | |
|---|---|
| 목표 | 포폴 완성 → 데모로 수요 검증 → **숫자가 나오면** 상용 |
| 인원 | 2인. 기존 분업 유지 (A 엔진·AI / B UI·콘텐츠) |
| 중단 기준 | 각 단계 끝에 게이트가 있다. 통과 못 하면 다음 단계로 안 간다 |

**단계마다 게이트를 두는 이유**: 이 게임이 재미있는지 아직 아무도 모른다.
2인 10일로 만든 것이라 완주 검증조차 안 끝났다. 재미를 확인하기 전에 시나리오 12개를 쓰면
그 노력이 통째로 버려질 수 있다.

## 3. Phase 1 — 포폴 완성 (3~4주)

게이트 0을 통과했다는 전제. **보여줬을 때 완성돼 보이는 상태**가 목표다.

### A. 게임 내용

| 항목 | 지금 | 목표 | 왜 |
|---|---|---|---|
| **신뢰도 누적** | 없음 | 위증 발각·이의제기 성패가 이후 AI 판단에 남는다 | 지금은 라운드 간 기억이 얕아 심리전이 얇다. **이 게임의 코어가 사는 지점** |
| **에이전트 성격** | 폴백 대사만 갈림 | 거짓말 성향·화법을 프롬프트로 분리 | 5명이 비슷하게 말하면 "AI 5명"이 아니라 "AI 1명 ×5"로 읽힌다 |
| **시나리오** | 4 | 6 | 12개는 상용 단계에서. 포폴엔 6개면 충분하다 |
| **직업 밸런싱** | 10종 배정 확률만 확인 | 승률 기반 조정 | 오프라인 시뮬레이션으로 잰다 (LLM 비용 0) |

**신뢰도를 1순위로 둔 이유**: "거짓 반증"이 코어인데, 거짓말한 사람을 이후에 어떻게
대하는지가 게임에 반영되지 않으면 위증이 그 라운드에서 소비되고 끝난다.
누적되어야 "쟤는 이미 두 번 걸렸다"는 판단이 생기고, 그때 비로소 심리전이 된다.

### B. 디자인

아래는 배포본 화면 5장을 직접 보고 적은 것이다. 못 본 화면(반증 공개·판결)은 제외했다.

| # | 관찰한 문제 | 방향 |
|---|---|---|
| D-1 | **테이블 화면에 시선 우선순위가 없다.** 좌측 참가자 5명과 우측 추리표가 같은 무게로 깔려 있어, 처음 보면 어디부터 볼지 모른다 | 지금 차례인 것 하나만 밝히고 나머지는 눌러 대비를 만든다 |
| D-2 | **참가자가 「참가1·참가2」로 표시된다.** 캐릭터 이름(임세라)이 부제로 작게 붙어 몰입이 깨진다 | 이름을 주(主)로, 참가 번호를 보조로 뒤집는다 |
| D-3 | **추리표가 스프레드시트로 보인다.** 1935년 경성이라는 톤과 어긋난다 | 수첩·괘지 질감으로. 체크 표시도 손으로 그은 흔적처럼 |
| D-4 | **테이블 중앙 일러스트가 거의 안 보인다.** 어둡게 깔려 공간감이 죽었다 | 중앙을 비우지 말고 판의 무대로 쓴다 |
| D-5 | **밀담 패널이 빈 채로 큰 자리를 차지한다.** 라운드 끝에만 열리는데 항상 떠 있다 | 닫힌 상태를 접고, 열릴 때 존재감을 준다 |

**공통 원칙**: 지금 화면은 정보를 다 보여주지만 **무엇이 중요한지는 안 알려준다.**
정보를 빼는 게 아니라 층을 나누는 작업이다.

기존 제약은 유지한다 — `transform`·`opacity`만 쓰는 애니메이션, CSS 변수 토큰,
UI 프레임워크 미도입.

### 게이트 2 — 상용 진입 여부

이 단계는 **숫자로 판단한다.** "느낌이 좋다"로 넘어가지 않는다.

- [ ] 위시리스트가 유의미하게 쌓이는가
- [ ] 판당 원가 × 예상 플레이 횟수가 **판매가 안에 들어오는가**
- [ ] 에셋 권리가 정리됐는가 (3-C 확인 결과)

셋 중 하나라도 아니면 **포폴로 마감한다.** 그것도 실패가 아니다.

## 5. Phase 3 — 상용 (조건부 · 6~12개월)

게이트 2를 통과한 경우에만.

### 사업 구조

핵심 질문은 하나다. **판매는 1회, API 비용은 플레이할 때마다.**

| 방식 | 원가 | 문제 |
|---|---|---|
| 기본 오프라인 + **AI 모드 옵션** | 낮음 | 두 경로를 다 관리 |
| 로컬 소형 모델 내장 | 0 | 번들 수 GB, 저사양 배제 |
| 폴백 풀 대폭 확대 | 0 | 대사 반복이 티남 |
| BYOK | 0 | 일반 유저는 못 씀 |

**첫 번째를 권한다.** 이 프로젝트는 **LLM 없이도 완주되는 구조를 이미 갖고 있다.**
보통 LLM 게임이 상용화에서 죽는 지점을 이미 넘어선 상태라, 새로 짜는 게 아니라
비중을 뒤집는 작업이 된다.

### 남은 작업

- 시나리오 6 → 12~15
- 일러스트 — 권리 문제가 걸리면 재발주
- Steamworks 연동 (세이브·도전과제·클라우드)
- 국내 출시 시 **GRAC 등급 심의**
- QA·현지화

## 7. 우선순위 한 줄

> **완주 확인 → 원가 측정 → 신뢰도 → 테이블 화면 정리 → 데모.**

이 순서를 지키는 이유는 뒤로 갈수록 되돌리기 비싸기 때문이다.
완주가 안 되면 신뢰도를 넣어도 볼 수 없고, 원가를 모르면 상용 설계를 시작할 수 없다.
